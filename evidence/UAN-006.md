# UAN-006 - Browser-only WebMCP slice

## Scope and evidence label

The WebMCP tests are simulated API/lifecycle fixtures. They are not a browser host test and do not
establish native WebMCP support. The implementation targets the current draft surface:
Document.modelContext.registerTool(tool, { signal }), with an execution AbortSignal passed to the
tool callback. The primary source is https://webmachinelearning.github.io/webmcp/. The package
does not rely on navigator.modelContext or a nonstandard unregisterTool API.

The package remains private: true. Local checks and the package tarball dry run are development
verification only; no npm release action is part of UAN-006.

## Verified simulated behaviors

The test modelContext accepts current-draft tool dictionaries and registration AbortSignals:

- Public read tools are projected by default; protected tools are hidden unless canExpose opts them in.
- The shared executor validates input, selects only the browser binding, and authorizes each call.
  Denial blocks the binding.
- Resync replaces prior registrations; retained callbacks fail after revocation; repeated adapter
  initialization reuses one adapter.
- Resync after logout removes a previously opted-in protected tool. pagehide on the owning Window
  aborts registrations. Rapid resync reports only current tools.
- Unsupported modelContext preserves the page path and returns supported: false without throwing.
- A registry with only server bindings produces no browser registrations.
- The browser entry import graph contains no Node builtins, HTTP/MCP adapters, MCP SDK import or
  server-only secret fixture. E06's actual Vite output also passed sentinel/import checks.

E06 has a normal human button and a page-local theme binding. Agent and human paths use the same
binding; the browser-to-server request fails with binding-unavailable because no remote binding
exists. E12 runs the same converter implementation through explicit local and browser bindings.

## Limits

No real browser, in-browser agent, Chrome origin trial/flag, or native WebMCP host was used.
Unsupported-browser behavior is simulated; actual rendering and keyboard interaction were not
browser-tested. Browser lifecycle cleanup depends on consumers calling sync after route/auth
changes; pagehide cleanup is registered on Document.defaultView. No server fallback is invented
for E06.
