# Run the framework and browser examples

Use Node 24 and npm for the example matrix. In the repository root run `npm ci`, `npm run build`, and `npm pack`. Each framework is an independently locked installation. In the framework directory run `npm ci`, then `npm install --no-save --package-lock=false PATH_TO_ARCHIVE` to test the packed SDK. Without that install, the examples use the built SDK from the repository root. In `examples/readability/checks`, run `npm ci` and `npx playwright install chromium`.

Set `SITE_URL` to a loopback origin with an explicit port. The default is `http://127.0.0.1:4173`. Set `READABILITY_EDITION=original`, run `npm run build` in the framework directory, then run `node verify.mjs FRAMEWORK --http-only` from the checks directory with the same edition. Set `READABILITY_EDITION=updated`, rebuild, and run `node verify.mjs FRAMEWORK`. The checker starts the production server, checks public responses and the retired mirror, opens a clean Chromium page and exercises the showcase interaction. It closes the server when finished. On Linux, an existing Chromium executable can be supplied through `READABILITY_CHROMIUM`.

Each production build writes a private review manifest under `generated/` and approved files into the framework's public asset directory. The examples also expose a build witness at `/agent-native-witness.json`. For a live verification campaign, choose a fresh synthetic alphanumeric `READABILITY_PROOF_CODE` (12–64 characters), set it before building all eight examples, and configure `SITE_URL` with the actual public base. This value is intentionally visible to a reader who follows the public guide. Give a test agent an entry URL and question, then check the fact against the separate answer key. The witness records the public projection digest, edition and optional proof-code digest. Keep credentials out of this field.

The [matrix workflow](https://github.com/uppercut-labs/agent-native/blob/main/.github/workflows/readability-frameworks.yml) installs the archive and runs original and updated production builds for each framework. These jobs use loopback HTTP. The same production site can be verified after deploying by running the installed CLI's `verify --manifest generated/manifest.json` against its configured public base. Keep `generated/`, the private ownership state and the source checkout out of any static hosting root.
